# Monitor Tool

一个面向 Windows 的轻量硬件状态监控桌面端原型。它提供可配置的桌面浮窗、实时仪表盘和按需展示的硬件指标。

## 作者与项目

- 作者：CarlCloud
- GitHub：[CarlCloud-dev/Monitor-tool](https://github.com/CarlCloud-dev/Monitor-tool)

## 当前能力

- CPU 利用率、频率与可用时的温度
- 内存利用率、已用容量与可用时的 DIMM 温度（多条内存显示最高温，详情列出各条读数）
- GPU 利用率、温度、显存利用率、显存已用容量（保留一位小数 GB）与设备信息（取决于显卡驱动可提供的数据）
- 自带 Libre Hardware Monitor 本地桥接：温度、功耗、风扇与主板传感器
- 可选“管理员增强采集”：仅提权本应用自带的桥接器，以尝试读取 CPU MSR、Super I/O 与主板风扇；不依赖或启动 HWiNFO
- 磁盘利用率、上下行网络速率
- 桌面浮窗：置顶、锁定/鼠标穿透、透明度、比例、紧凑/展开/横向布局与位置记忆
- Windows 11 任务栏监控：独立开关，靠左、居中、靠右放置，复用浮窗显示项并避开任务栏控件；空间不足时截断内容。
- 任务栏显示采用原生子窗口与透明圆角绘制，随任务栏保持层级；布局探测与绘制进程独立，开始菜单导致布局查询阻塞时保留已有位置。实现及验证方法见 [任务栏显示说明](docs/taskbar-display.md)。
- 托盘右键可分别切换桌面浮窗与任务栏监控；设置中的两组参数按各自开关状态展开或收起，关闭后保留原设置。
- 通过“显示项”勾选并拖动排序浮窗内容；设置会持久化到当前 Windows 用户的应用数据目录
- 实时页保留最近 120 个采样点的短时趋势图
- 独立历史趋势页：可开关本地日志、单独选择长期记录指标，按 7 / 30 / 90 / 180 天最长周期保留，超期记录自动清除
- 可选 CPU/GPU 温度阈值告警；默认关闭，同一告警使用冷却时间避免重复通知
- 关于页显示当前版本，支持启动检查更新、主题更新弹窗、内置下载并启动 Setup 安装器，以及手动下载；启动检查可关闭
- 轻量模式：关闭主界面后释放主界面渲染进程，仅保留浮窗、托盘与传感器；需要设置或历史曲线时从托盘重新打开

轻量模式下，采集服务会按浮窗与历史记录的勾选项建立采集计划；未使用的内存容量、磁盘、网络、频率等指标不会重复调用对应系统接口。Windows 磁盘/网络计数器共用一个按需启动的常驻 PowerShell worker，不使用时会自动退出。若开启温度告警，CPU/GPU 温度会继续后台采样。历史日志按 UTC 日期分片保存，保留周期变化和清理时只处理相关分片，历史页也会缓存未变化的分片，避免长期运行时反复重写或解析一个大文件。

历史曲线的查看范围与保留周期、记录指标相互独立。默认查看近 24 小时，可快捷查看近 1/6/24 小时、7/30 天或全部，也可定位本地时间的某小时、某一天、某一周（周一到周日），或设置精确起止时间。支持前后翻页、单指标筛选、悬停/方向键读数、拖动框选放大及返回缩放前范围，并显示区间末次、最低、平均和最高值。近 24 小时以内的快捷视图随新记录更新；长周期、指定日期和自定义范围采用快照，手动点击刷新更新。默认最低保留 7 天，旧版不足 7 天的设置会迁移到 7 天，原 30 天设置保留；已清除的历史不会恢复。

历史查询只打开覆盖所选区间的日期分片；较大分片及旧版单文件日志使用流式读取。曲线按时间桶保留首尾和峰谷，每个指标最多返回 1200 个概览点，统计基于区间内全部记录；缺测和停机段保持断开。缩小范围后重新查询细节，不会对概览点插值补造数据。查询可取消，切换范围、离开页面或最小化后不会继续积累整段长期日志到内存。

开机自启、主窗口最小化或隐藏时都会按设置进入轻量采样；隐藏的浮窗不再接收逐秒刷新，浮窗不需要的指标仍可由历史记录或温度告警单独采集。Windows 内存和 CPU 型号/频率通过原生接口读取，不再为分页文件等未显示的数据反复启动 PowerShell。CPU 温度、GPU 利用率/温度/显存优先复用增强传感器；温度缺失时的 ACPI 回退也由常驻 worker 查询，并缓存 10 秒（ACPI 是否上报以及对应的温度区域取决于设备）。NVIDIA 回退采样直接查询 `nvidia-smi`，不再逐秒枚举所有显示器。无 NVIDIA 工具时的显卡信息回退每分钟最多刷新一次。

可通过 `powershell -NoProfile -File scripts/profile-runtime.ps1` 只读统计运行中的程序与已捕获子进程的 CPU 占用。`node scripts/profile-sampling.mjs` 可单独观察当前源码的实际采样服务（不写设置或历史，不请求管理员权限）；输出 PID 后，可使用前一个脚本的 `-RootProcessId` 参数单独统计其进程树。此结果不包含 Electron 浮窗渲染开销。

如需检查真实浮窗、托盘和采样的合计开销，可运行 `node_modules\electron\dist\electron.exe scripts\profile-desktop.cjs`（追加 `--panel` 同时打开主面板）。诊断会使用临时数据目录和标准权限传感器，不改正式设置及 Windows 自启项，并在约 40 秒后自动退出。日志直接保存为系统临时目录中的 `MonitorTool-desktop-<PID>.jsonl`，避免启动终端关闭后产生管道写入错误。使用 `profile-runtime.ps1 -RootProcessId <PID>` 统计对应的完整进程树；单独观察 Electron 主进程会漏掉采样子进程。刷新间隔变化会复用现有采集器，退出后的过期异步结果会被丢弃，避免退出途中重新启动采样进程。

## 启动

更新通道的本地配置与服务端响应说明见 [更新通道文档](docs/update-channel.md)。项目作者的通道 token 放在 Git 忽略的 `update-channel.local.json` 中，构建时随资源带入；源码仓库不保存实际 token。GitHub Releases 与应用内更新通道分别维护版本和安装包。

```powershell
npm install
npm start
```

## Windows 正式程序

开发模式下运行的进程名仍会显示为 Electron；正式打包后会使用 `Monitor Tool` 产品名、`MonitorTool.exe` 可执行文件名和项目 Logo。

```powershell
# 生成可运行的未安装目录，用于检查进程名称与图标
npm run pack

# 生成 Windows 安装包
npm run dist
```

## 传感器边界

基础的 CPU、内存、磁盘和网络数据不需要管理员权限。温度、风扇、部分功耗与主板传感器受设备、驱动和 Windows 安全策略影响，可能不可用；界面会显示“暂不可用”，不会以猜测值替代。

内存温度复用内置 Libre Hardware Monitor 采集器，仅取物理 DIMM 的实时 SPD 温度，排除温度上限、分辨率、显存温度及 CPU 内存控制器温度。可在浮窗显示项和历史趋势中分别勾选“内存温度”；不会自动改变原有选择。多条内存取可读最高温，主界面详情悬停可查看各条读数。能否读取取决于内存是否带温度传感器、主板/SMBus 访问和驱动权限；标准模式无读数时可尝试已有的“管理员增强”，不需要另装 HWiNFO。70°C/85°C 仅为界面颜色提示阈值，不代表所有内存型号的安全温度上限。此功能复用既有采样频率和缓存，不新增轮询进程。

“增强硬件传感器”默认开启。应用会启动随程序打包的 Libre Hardware Monitor 0.9.7-pre731 本地桥接进程并按需读取数据，不会把传感器数据发往网络。该官方预发布库已含 MSI X870(E) / Nuvoton NCT6687D-R 的适配代码；桥接器会保留主板与 Super I/O 子设备层级，因此风扇与主板温度不会因设备树扁平化而丢失。

默认“标准”模式不请求管理员权限。若设置页显示 CPU 温度/功耗已识别但数值无效，或主板/CPU 风扇未上报，可由用户切换到“管理员增强”；此时 Windows 会显示 UAC，由用户自行确认。该模式不会修改 BIOS、风扇曲线或 Windows 安全设置；如果仍无读数，应用会如实显示不可用而不会伪造数据。

新版 LHM 对主板 Super I/O 需要 PawnIO 底层驱动。项目已内置官方签名的 PawnIO 2.1.0 安装器：管理员增强模式检测到缺失时，设置页会显示“安装传感器驱动（内置 · 仅一次）”。用户点击后由应用校验 SHA-256、请求 Windows UAC，并等待官方安装器完成；安装成功后应用自动重连传感器。它不是常驻的 HWiNFO 类监控程序，也不会下载未知文件、修改 BIOS 或写入风扇控制值。

## 第三方组件

`resources/lhm/` 包含 Libre Hardware Monitor 0.9.7-pre731 的运行文件，以及本项目的标准/管理员增强 JSON 桥接程序。Libre Hardware Monitor 使用 MPL-2.0；发布产品时请一并保留该目录中的第三方说明，详情见 `resources/lhm/THIRD_PARTY_NOTICES.md`。
